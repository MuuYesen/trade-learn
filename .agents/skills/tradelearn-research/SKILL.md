# 量化研究流程

一次回测是一次**测量**，不是结论。这份 Skill 规定怎么把测量做干净、怎么从测量走到结论；不讲接口细节。接口以当前安装的 TradeLearn 为准：先读 README，拿不准时用 `help()` 或 `inspect` 查已安装版本的真实签名，不要照搬旧教程。

用用户的语言回复。

## 七条原则

1. **先立题，后写代码。** 机制、证伪条件、判定标准和样本切分，在看到任何结果之前写下来。
2. **样本外只用一次。** 看过测试段再回去改，测试段就成了训练段。
3. **看一片，不挑一点。** 单组参数是一个带噪声的估计；报告稳定区域的整体表现，不报"最优参数"。
4. **每个数字都带误差和尝试次数。** 没有标准误、没写试了多少组的夏普，无法解读。
5. **惩罚策略。** 成本往高里估、成交往差里算；要找的是"最不容易坏"的策略，不是纸面上赚得最多的。
6. **"没有显著的净收益"是合格的结论。** 大多数想法的正确结论就是它。一个永远给不出否定结论的流程，不是研究流程。
7. **缺失的证据不是通过。** 没检查的写"未检验"，数据不够的写"无法判断"；已证实的问题和缺少证据的地方分开写。

## 开始之前

**环境**
- Python 3.11 及以上，在虚拟环境里安装 `trade-learn`。系统 Python 常因 PEP 668 拒绝安装，直接建虚拟环境，不要绕过系统保护。
- 需要实验记录、因子检验、研究工具时，安装 `trade-learn[research]`。

**用户没说清的，先用默认值开始，不要先反问**，并在报告开头写明用了哪些默认值：

| 未指定 | 默认 |
|---|---|
| 区间 | 最近 5 年以上；不同行情（涨、跌、震荡）至少各有一段。数据不足就用全部，并写明 |
| 频率 | 日线 |
| 切分 | 按时间，最后约 30% 作测试段 |
| 成交 | 信号出现后的下一根 bar 开盘成交 |
| 成本 | 该市场常见费率加滑点（见 `references/china-market.md`）。**TradeLearn 的回测默认手续费是 0，必须显式设置** |
| 基准 | 同一标的买入持有 |

**判断你在哪种环境**
- 能 `from tradelearn import sentinel`，并且环境变量里有 `LEAFQUANT_ENDPOINT`：你在用户跑实盘的服务器上，可以做实盘复盘。
- 否则（例如 Muse 这类云电脑）：只做研究。用户要复盘时，告诉他复盘要在跑实盘的那台机器上进行。

## 流程

每一步结束有一道**关卡**。关卡没过就是一个发现，不要绕过去继续。

### 1. 立题

在写任何代码之前写下：

- **机制**：为什么会赚钱？交易对手是谁、他为什么一直愿意站在另一边？合格的答案是风险补偿、被迫的交易（调仓、到期、强平）、某类参与者受到的约束、信息扩散慢。"RSI 在这个品种上好用"、"回测看起来不错"不是机制。没有机制也可以研究，但要写明这是在噪声里搜索，并预期结论大概率是否定的。
- **规则**：入场、出场、仓位、过滤条件、标的范围，写到不需要任何主观判断。
- **时序**：用一句话写清事件顺序，例如"t 日收盘后数据可得 → 用截至 t 的数据算信号 → t+1 日开盘下单"。每个输入什么时候真正可以拿到，都要落在这条线上。
- **对照**：同时定好简单基准（买入持有、等权、波动率缩放等），必要时加一个打乱信号的安慰剂版本。
- **证伪条件与判定标准**：什么结果就放弃，例如"测试段年化夏普低于 0.3"。比较多个方案时，事先定好用哪个指标判胜负。
- **切分**：训练段与测试段的日期，现在就定下来。
- **尝试计数**：从这里开始记录每一个试过的参数组合、标的、变体。第 5 步要用这个数，事后无法还原。

**关卡**：上面五项都写在报告草稿或实验记录里。

### 2. 数据

列一张数据表：来源、标的、区间与根数、频率、时区与交易时段、复权方式、缺失与跳空、停牌和成交量为 0 的 bar（这类 bar 上的订单可能永远不成交）。

逐项检查：复权是否会改写历史、缺口是否被前值填平（跨过暴跌的缺口会美化一切）、多标的是否对齐了不同的交易日历、标的池是否包含已退市的标的（幸存者偏差是假收益的最大来源）、基本面和宏观数据是否按**发布时间**而不是所属期使用。

跑任何东西之前，先把原始价格画出来看一眼：平台段、尖刺、拼接痕迹，肉眼比断言快。

**关卡**：数据表写进报告。

### 3. 如实回测

- **成本**：手续费、滑点、资金费、融券费。说明每个数的依据，不接受默认值。
- **成交时点**：信号用当根收盘价计算，就只能在下一根成交。用"收盘信号、收盘成交"的回测，每笔交易都偷看了一点未来。A 股还要处理 T+1、涨跌停买卖不了、停牌卖不出（见 `references/china-market.md`）。
- **前视偏差**：所有滚动统计只用到当根之前的数据；标准化、去极值、特征选择、阈值只在训练段拟合；用未来收益做标签时按标签结束时间剔除跨界样本。方法见 `references/validation.md`。
- **样本量下限**：数**有效观测数**，不是交易笔数。持仓重叠、标的相关的交易本质上是同一笔赌注记了很多次。有效观测不足约 30 个，指标没有意义；显著性检验用按时间段（如日收益）计算的统计量，**不要用按交易笔数算的 t 值**——交易越频繁它越虚高。
- **期末持仓**：期末仍持仓要单独说明未实现盈亏。
- **引擎**：日内、限价/止损单、部分成交、路径相关的规则，用逐事件撮合的引擎（TradeLearn 的 Engine），不要用向量化的快速回测近似。
- **先扣掉成交不了的收益**：回测里按收盘价全额成交、实盘却买不到卖不掉的那部分收益，是系统性偏正的。先按市场规则修正成交，再做第 4、5 步的统计检验——在含有这部分假收益的曲线上算紧缩夏普，扣的是错的分子。A 股的检查顺序见 `references/china-market.md`。
- **没计成本的结果标成"毛收益"**，不得据此说可以交易。

**关卡**：成本已计入、前视检查干净、有效观测数过下限。**单组参数夏普超过 2（日频）先当成 bug 排查**，再考虑是不是真的好。

### 4. 参数曲面

- **网格**：选承载假设的参数轴，范围要大到能看见稳定区域的**边界**。
- **扫描**：组合数要足够看清形状，不是十几个点。
- **平滑**：每个格子取它和邻近格子的平均；原始最优点往往是网格里最响的噪声。
- **误差**：年化夏普 S、样本 T 年时，标准误约为 `sqrt((1 + S²/2) / T)`。4 年夏普 1.0 的标准误约 0.61——两组参数夏普差 0.2，就是同一组参数，排名没有意义。
- **稳定区域**：保留平滑后指标与最优值相差**不超过一个标准误**的全部组合，这个区域才是优化的真正产出。
- **取区域整体**：把区域里的组合等权合起来作为结论，不挑其中一个。孤立的尖峰是拟合出来的；平滑后就消失的"高原"从来不是高原。

**关卡**：存在一片稳定区域，并且平滑后仍然存在。参数热力图放进报告。

### 5. 扣除运气与搜索

刚才的搜索本身制造了收益，要把它扣掉。一个好看的结果可以由四种原因解释：**运气、搜索、行情、错误**。逐一排除，再看是否**脆弱**：

| 要排除的 | 怎么查 |
|---|---|
| 运气 | 夏普的置信区间；考虑序列相关的标准误；有效观测数 |
| 搜索 | 写明总尝试次数 N，报告**紧缩夏普**（Deflated Sharpe）；有条件时算回测过拟合概率（PBO）；滚动验证 |
| 行情 | 与买入持有的差值是否显著；随机择时（打乱入场时点）作对照；分年度、分行情 |
| 错误 | 收益能否用持仓和价格重建出来；把未来数据换掉后过去的信号是否不变；结果是否"好得不像真的" |
| 脆弱 | 成本 ×2、×3；找出收益归零的**盈亏平衡成本**；去掉最赚的几天、最好的一年后还剩多少；换相近标的 |

滚动验证时，**每一折都重做第 4 步的区域选择**，向前带的是区域整体，而不是每折重新挑最优点——后者验证的是一个你实际上不会使用的流程。

公式、阈值和判读见 `references/validation.md`。

**关卡**：核心检查都有结果，没做的写"未检验"。

### 因子研究的附加要求

研究截面因子（选股因子）时，因子**先当嫌疑人**：只有通过时点、样本、成本、样本外四道检查，才能称为 alpha。

- **时点**：每个字段何时发布、何时可得、何时可交易；财报按首次披露版本对齐（见 `references/validation.md` 第十一节）。发现未来信息，先重写因子，不继续回测。
- **样本**：剔除或单独处理停牌、ST、上市未满一定期限、涨跌停、低流动性和陈旧价格；不用今天的成分股构造历史股票池。
- **变换**：去极值、截面标准化或排序；**只在有研究动机时**做行业、市值、beta 中性化，并说明为什么。
- **评价**：IC、Rank IC、IC_IR、分组收益的单调性、多空收益、换手、成本后收益、IC 衰减与半衰期、分行情表现。
- **区分来源**：正交掉行业、市值和已有因子后还剩多少，才是新信息；正交前后的 IC、收益、换手并列。

做法见 `references/validation.md` 第十节。

### 6. 结论与记录

用第 1 步写下的判定标准下结论，**不在看完结果后移动门槛**。如果门槛现在显得不对，明说这一点，而不是悄悄改掉。结论分三级（详见 `references/report.md`）：

- **未证实**：任一核心检查没通过（测试段不显著、紧缩夏普不过关、成本翻倍就亏、收益集中在一两年或少数几天、能被随机择时或买入持有解释）。写"没有显著的净收益"，不写"策略无效"。
- **证据不足**：核心检查都通过，但有多项警示，或样本不够。下一步是在**新的**数据或市场上检验，不是在同一份数据上微调重跑。
- **目前可信**：全部通过。下一步**只能是模拟盘**，并在第一笔实盘之前写好停用条件（见 `references/live-review.md`）。

策略或因子没通过时，判断更像哪一类原因：**数据问题、逻辑问题、成本问题，还是行情变化**。给出最多三个最值得做的下一步实验，不泛泛罗列。

记录：每次运行都记进实验记录——Lite 回测用 `Backtest.log_mlflow(...)`，其他结果用 `tradelearn.integrations.mlflow.log(...)`，连同尝试计数和失败的方案一起记。为了让别人（包括半年后的你）能复现，同时记下：数据来源与快照（区间、根数，可以的话附文件哈希）、代码版本、主要依赖版本、全部参数、随机种子和运行命令。同一个指标在不同地方对不上时，列出来，不要默默挑一个。之后要对比时直接取记录，不要重跑旧方案。

### 7. 实盘复盘与优化

实盘的问题从"有没有收益"变成"还有没有"。有 Sentinel 时，先读它已经算好的执行复盘、延迟、归因和看板时序，以它为准；再把实测的滑点、延迟、成交率代回回测，提出改进、重新验证，交用户决定是否上线，上线后按版本对比前后。拉取实盘数据，和**模拟分布**而不是单条回测曲线对照；用实际成交校准成本，把执行成本拆开看；把偏差分到信号、行情、数据、执行四类原因上；用事先写好的停用条件判断，不因为几个月的好坏临时干预。详见 `references/live-review.md`。

## 不要给出这些

即使用户直接要，也不给；改为给出下面右栏的东西，并说明原因。拒绝帮忙不是目的，拒绝帮用户骗自己才是。

| 不给 | 改为给 |
|---|---|
| "最优参数是 X" | 稳定区域及其整体表现 |
| 不带标准误和尝试次数的夏普 | 区域均值 ± 标准误，写明 N |
| 不计成本的回测结论 | 计入成本的结果，加盈亏平衡成本 |
| 结论前偷看测试段，或在用过的测试段上继续迭代 | 新的测试区间 |
| 有效观测不足 30 时的结论 | "样本不足，无法判断" |
| 按交易笔数算的 t 值 | 按时间段收益算的统计量 |
| 用历史最大回撤当风险预算 | 模拟出来的回撤分布的尾部 |
| 只在样本内成立时写"更优""有效" | "样本内表现更好，待样本外验证" |

## 报告里的数字

报告由你自由组织，可以加解读，但：
- 收益、夏普、回撤等指标**引用 TradeLearn 的计算结果**，写明口径（年化用了多少期、是否扣无风险利率）
- 再用权益曲线**独立复算一遍关键指标**作为核对；对不上就说出来，不要选一个好看的
- **头条数字必须是：测试段、扣除成本、无前视偏差的结果**。样本内、未扣成本的数字只能作为对照，并标明
- **测量和解读分开写**："测试段夏普 0.64 ± 0.32"是测量，"这是个好策略"是解读
- **失败的部分也要写**：没成立的年份、没出现的标的、把收益吃光的成本水平
- 有 Sentinel 数据时，实盘数字**以 Sentinel 的口径为准**

## 边界（任何时候都适用）

- **不发起实盘交易。** 改动实盘的任何东西——策略代码、参数、重启——都要用户对每一次改动明确确认。
- 不调用付费数据源，除非用户明确要求。
- **不要把任何凭据写进你会读或会改的文件。** 凭据只通过环境变量交给实盘进程。
- 这是研究工具，不给投资建议，不预测收益，不建议仓位大小用于真实资金。报告结尾写明：本报告仅供研究参考，不构成投资建议。
