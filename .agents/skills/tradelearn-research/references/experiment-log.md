# 实验记录：尝试台账、数据使用记录、事前登记、复现

紧缩夏普、Reality Check 和"样本外只用一次"都依赖记录：尝试次数少记一点，DSR 就偏乐观；测试段被看过却没记下，"样本外"就名不副实。这些事后无法还原，从第 1 步开始记。

## 一、尝试台账

- 记下在**这份数据**上试过的一切：网格里的每组配置、每个标的、每条规则变体、过滤条件和多空规则的选择、更早版本的模型和选择流程、机器学习的特征集、标签定义、超参数和随机种子。计的是**看过的**结果，不是保留的结果：丢弃的运行、放宽过的网格、换掉的指标都算。
- 粗算：`尝试数 = 组合数 × 标的数 × 变体数 × 重启次数`。量级比精确重要（`validation.md` 第五节）。
- 转向（换信号来源、换持有期、换结构）和每一轮"改了再审"都是新的尝试。
- **不计入**：事先登记、只用作压力测试而不用来挑方案的成本情景；CPCV 的路径；同一配置的重跑。用某个成本假设去挑方案时，那就是一次选择，要计入。
- 台账**永不清零**：DSR、Reality Check 的 N 和候选集都从这里取。
- 每跑完一个配置就**立即登记**，不在最后批量写（中途崩溃会丢掉全部记录）。旧的、失败的运行不删除，只标"已被取代"。
- 每个配置用确定性哈希（参数按键排序后取 SHA-256，覆盖模型、超参、特征版本、数据版本、随机种子）作为登记键：同一配置重跑落到同一槽位，可以据此去重。预测结果带折编号，否则无法重建样本外表现。

## 二、数据使用记录

**看过结果的数据，不能再当独立验证。** 按数据段登记，每段一行：

| 字段 | 内容 |
|---|---|
| 数据哈希 | 内容指纹（同一时期、同一内容的数据，改名、换目录、重新下载，哈希不变，**不算新数据**） |
| 区间与范围 | 起止日期、标的 |
| 角色 | 训练 / 验证 / 测试 / 前向 |
| 状态 | 未触碰 / 已查看 / 已用于选择 / 测试已消耗 |
| 记录 | 何时、哪次运行、看了什么指标 |

- **在测试段上运行任何东西之前**，先把"这段测试数据已被使用"写进只追加的记录。运行成功、失败、中途报错都算用掉一次。
- 测试段报告生成失败（例如序列化出错）时，不重跑测试段：只重算开发段，测试段的指标从已写记录里读，缺的填"缺失"。
- 样本外评估结果已存在时，默认拒绝覆盖；只有用户明确要求才替换，并记下来。
- 换一个方案名、换随机种子、换文件名，都不能让已消耗的测试段恢复成"未触碰"。

**测试段会被悄悄用掉的方式**，发生任何一种，状态改为"已查看"：
1. 看到哪些标的表现好之后才确定标的池；
2. 修了一个只因为样本外很差才发现的"bug"；
3. 区域或模型框定之前"只是看一眼"样本外；
4. 同一研究计划里多个策略或多个想法共用同一段样本外；
5. 从样本外里挑报告里好看的子区间；
6. 你或别人已经在这段历史上跑过这个想法、看过它的结果（以前的研究、别人基于同一份数据的报告）。

已发表的想法（动量、价值等）本身不让测试段变成"已查看"，但要记一条警示：写明想法来源，结论措辞相应保守（已发表的效应常在发表后衰减）。

用掉之后：在报告里明说，把研究降为"仅样本内"，另留新的数据（更晚的时期或其他标的）再下结论。看过结果之后修订的分析计划标为"**回顾性修订**"，不能称为事前登记，看过的那段也不能叫"未见的确认集"。

**机制化**（条件允许时）
- 开测试段前，逐项比对数据、切分、股票池、预处理、模型和搜索配置与冻结时一致，不一致拒绝运行。
- 研究代码运行前做静态扫描：命中读取测试段产物的写法（测试数据加载、测试指标文件、判分模块）就拒绝运行。
- 数据或切分定义的哈希变了，研究阶段整体重置：新旧数据下的分数不放在一起比。
- 部分运行标记为"不完整"，不能写成完整成功。
- 交给下游的只能是冻结模型的预测，真实标签不进导出文件。

## 三、事前登记与变更

在任何真实数据结果出来之前，写下并冻结：
- 机制、规则、事件时序、对照、证伪条件与判定标准（含与 `gates.md` 默认值不同的阈值）；
- 数据来源、各输入的可得时钟、切分日期、行情的定义；
- 完整网格、选择流程、成本情景（主情景和压力情景）、过拟合控制；
- **来源声明**：想法从哪来，在这份数据上是否已知有效（已发表、以前看过这段历史）。只有"想法在看这个市场的历史之前就已固定"才算干净。想法已发表的，记为警示，结论措辞相应保守；在这段历史上看过结果的，按第二节把数据段标为"已查看"。

之后每次改动登记一条"改了什么、为什么、在看到什么之后"，台账继续累计，不静默改已冻结的方案。**假设实质改变时回到立题重新开始**，不在下游结果上修补。每道门槛失败都写下否决理由，最终结论连同被否决的备选一起记。

## 四、可比性

- 把一条规则落到代码时隐含的解释选择做成命名参数：bar 时间戳代表起点还是终点、涨幅基准用前收盘还是开盘、回看窗口是否含当前根、信号后空几根入场、入场用下一根开盘还是信号根收盘、退出按收盘还是根内触价、是否施加 T+1、同一标的的冷却间隔。
- 全部口径参数加数据指纹取哈希。两次运行的哈希不一致时，**不输出差值**，只列出哪些字段变了。
- 上游（数据、标签、特征、配置）改了，下游全部重跑，不只重跑改动那一段。

## 五、复现信息与复现判定

为了让别人（包括半年后的你）能复现，每次运行记下：
- 数据来源与快照：区间、根数、内容哈希；查询参数和查询时间；大数据集按训练、验证、测试各段做确定性抽样哈希。
- 代码版本、主要依赖版本、全部参数、随机种子、运行命令。

复现时：
1. 先为每个要比的指标写明比对方法：完全相等、绝对误差容忍度、相对误差容忍度、集合相等、序列相等。没写比对规则，状态记"缺少比对规则"，不算复现成功。
2. 每项指标逐一标"一致 / 不一致 / 缺失"，全部一致才算"已复现"。
3. 外部数据拿不到或快照不一致时，复现记"失败"。**不能换一份替代数据再称为复现成功。**
4. 总体状态四档：已验证 / 部分 / 受阻 / 失败。发现高风险前视问题时，不能是"已验证"。
5. 结构化结果和日志、文本报告里的同一指标不一致时，优先用结构化结果，冲突保持"未解决"交给用户，不默默挑一个。

## 六、TradeLearn 的写法

- Lite 回测用 `Backtest.log_mlflow(...)`，其他结果用 `tradelearn.integrations.mlflow.log(...)`，连同尝试计数、失败的方案和数据使用记录一起记。
- 之后要对比时直接取记录，不要重跑旧方案。
- 接口以已安装版本为准，拿不准时用 `help()` 或 `inspect` 查签名。
