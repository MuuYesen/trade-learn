# 判定：门槛、顺序与默认阈值

这一页是所有"过不过"的唯一来源。其他参考文件给做法，判读线统一写在这里。

**下面的数字都是默认值，不是标准。** 它们来自公开 Skill 和文献的常用取值，彼此并不总一致，这里取了偏保守的一个。用户可以在第 1 步立题时改；改了要写进实验记录（改了哪条、改成多少、为什么），报告里列出与默认值不同的项。**看过结果之后不再改**；如果门槛现在显得不对，在报告里明说，不悄悄改掉。

## 一、判定顺序

按下面的顺序走，前一步不过，后面的结果不能把它推翻。

1. **验证链路是否有效。** 流程自检（`self-check.md`）通过、数据审计没有阻断项、指标能独立复算。不通过时结论是"**无法判断**"：先修流程，不评价策略。这一项通过只说明工具可用，不说明策略好。
2. **核心项（一票否决）。** 第三节任一项不过，结论就是"未证实"。
3. **其余检查。** 核心项全过，但有任一非核心检查不过、有核心检查没做、或样本不够（有效观测已过下限，但短于 MinTRL 等），结论是"证据不足"。
4. **全部通过，才是"目前可信"。**
5. **排名在最后。** 多个方案比较时，先淘汰没过门槛的，再在剩下的方案里按第 1 步事先定的指标排名（第五节）。

除第 1 步外，某项不过不是停下的理由：记为发现，把余下的检查做完并全部列出。只有第 1 步（验证链路）失败时停下先修流程。

**结论分级**（全 Skill 只在这里维护一份，SKILL.md 和 `report.md` 都引用这里）：

| 结论 | 条件 | 可以怎么写 | 下一步 |
|---|---|---|---|
| **无法判断** | 验证链路不成立，或第三节标"无法判断"的项不过 | "无法判断"及原因 | 先修流程或补数据，不评价策略 |
| **未证实** | 任一核心项不过 | "没有显著的净收益"、"样本内表现更好，但未通过样本外检验"；不写"策略无效" | 记录后放弃，或换新的假设 |
| **证据不足** | 核心项全过，但有警示项不过、有检查没做，或样本不够 | "初步结果支持，证据不足" | 在**新的**数据或市场上检验，不在同一份数据上微调重跑 |
| **目前可信** | 全部通过 | "在本次检验范围内表现稳健（区间：…）" | 只能是模拟盘，第一笔交易前写好停用条件（`live-review.md` 第一节） |

规则：
- **触发的项全部列出**，即使更靠前的一项已经决定了结论。不只报第一条。
- **不用加权总分。** 一个致命缺陷不能被其他漂亮指标平均掉。本来就该有约束力的条件，作为**上限**作用在结论上（结论 = 门槛允许的最高级与检查结果中较低的一个），不放进加权平均。
- 每条判定在同一行写出：检查名、观测值、门槛、比较方向、所用成本情景。多项同时出现时起一个组合名，例如"PBO 高 + DSR 不过"、"扣费后归零 + 高换手"。
- 另列一张**证据缺口表**：还缺什么（例如"测试段未运行"、"测试段已复用"、"时点元数据不足"），缺口不能写成通过。

**方法状态**（每项检查必须是下面之一，全 Skill 只在这里定义）：

| 状态 | 含义 | 对结论的作用 |
|---|---|---|
| **通过 / 不过** | 已检验，有观测值 | 按第三节的类别作用 |
| **不适用** | 前提不成立，例如固定候选没有搜索（曲面、DSR、PBO 不适用）、只做多日频策略没有杠杆、非 A 股市场没有涨跌停项 | 不限制结论；写一句原因。不能用"不适用"跳过本该做的检查 |
| **受阻** | 应该做，但能力或数据缺失：已安装版本没有所需接口且参考实现覆盖不了、数据缺发布时间、拿不到原文 | 写明缺什么；核心项受阻时结论最高"证据不足"，链路项受阻时"无法判断" |
| **未检验** | 应该做、能做，但这次没做 | 同"受阻"，并写为下一步 |

"不适用"只能由第三节"适用于"一栏的前提推出；拿不准时记"未检验"，不记"不适用"。

## 二、研究结论与上线许可分开

三件事分开判，互不替代：

| 项 | 回答什么 | 通过条件 |
|---|---|---|
| 验证链路 | 工具和流程有没有问题 | 第一节第 1 步 |
| 研究结论 | 这份历史数据支持什么 | 未证实 / 证据不足 / 目前可信 |
| 进入模拟盘 | 能不能开始积累前向证据 | 研究结论为"目前可信"，测试段是**首次使用**（`experiment-log.md` 第二节），停用条件已写好 |

- 研究结论"目前可信"但测试段已被复用，进入模拟盘一项为"**无法判断**"，不是通过。
- 从模拟盘到实盘看前向证据和上线阶梯（`live-improve.md` 第六、七节），**由用户决定**。任何一项通过都不等于上线许可。

## 三、默认阈值表

"核心"：不过即"未证实"。"警示"：不过即最高"证据不足"。"无法判断"：先补样本或数据。

**适用范围**：表里的数默认对应**日频**、事先写定市场时钟的研究。日内或周频研究先按市场时钟换算年化期数（`routes.md` 第零节），按年计的门槛（检验区间、MinBTL）按日历年数算，按观测计的门槛（有效观测数）按该频率的有效观测数算；"适用于"一栏的前提不成立时记"不适用"（第一节）。区间一律指双侧 95% 区间；"下限 > 0"表示整段在 0 以上，整段在 0 以下是**负证据**，同样判不过。

| 链路 | 符号翻转零假设 | 有选择或拟合流程时 | 样本外年化夏普 < 0.3 | 无法判断 | `self-check.md` 四 |
| 链路 | 植入已知效应（t≈5） | 有选择或拟合流程时 | 样本外找回，夏普 > 0.3 | 无法判断 | `self-check.md` 四 |

## 四、审计别人的回测或代码时：缺陷严重度

审计已有的回测（用户给的、别人写的）时，每条缺陷标一级：

| 级别 | 典型 |
|---|---|
| **阻断** | 收盘信号收盘成交、零成本、用今天的成分股回测过去、基准错配、财报用最新版本 |
| **重大** | 成本偏低、涨跌停或停牌没处理、大量扫参没有扣除、规模远超日均成交额 |
| **一般** | 单项轻微问题，不改变结论方向 |
| **提示** | 记录在附录，不进头条 |

- 严重度结合换手判断：零成本在极低换手时可降为重大，在高换手时就是阻断。
- 可信度由门槛决定：有 1 个阻断，**不可采信**；0 个阻断但 ≥ 2 个重大，谨慎采信；重大 ≤ 1 个，有条件采信。
- 每条缺陷附证据（代码行号，或检查输出的文件名和关键数字），没有证据不下判定；每条修复附一个"复检动作"，说明改完怎么证明改对了。
- 偏差清单里这些项必须逐项写明状态，缺一项就不能判通过：前视、幸存者、标的池选择、退市、财报时点、复权、成本与滑点、融券可得性、流动性与容量、参数多重性、样本外、基准、行情依赖。

## 五、多方案比较：先门槛，后排名

1. 每个方案独立走完第一到第三节，得到各自的**绝对结论**（有没有显著的净收益）。
2. 没过核心项的方案出局，在报告里列出出局理由。比较本身仍可以报告，但只能写成相对结论。
3. **相对结论看配对差**：所有方案在同一区间、同一成本和年化口径下，按同一时间索引对齐收益，计算"候选 − 基准"的夏普差（或事先定的那个指标的差）及其区间，块长事先定。不用两个方案**各自的标准误**相加或比较来判并列——同一行情下的两条曲线高度相关，各自的标准误会把差异的误差算大好几倍，也可能算小。
   - 区间下限 > 0：候选更好；跨 0：并列，不排先后；上限 < 0：候选更差。
   - 多于两个方案时，以事先指定的基准逐一配对，并报多重检验折扣（候选多时做 Reality Check）。
4. **绝对与相对互不推出**：两个方案都"未证实"时，"候选显著少亏"是合格的相对结论，但不能写成候选有正收益；一个方案正收益显著，也不能推出它比另一个好。两项结论分开写，各自写证据方向（正 / 不显著 / 负）。
5. 并列时选更简单的（参数更少、条件更少），理由同第 4 步的区域：在噪声内挑最好，挑的是噪声。
6. 候选是事先固定的（没有在这份数据上挑选过），N = 候选数，全网格曲面与 DSR 记"不适用"（N = 1 报 PSR）；看过结果后增删、调整候选，就是搜索，按搜索计 N 并做曲面。但用户问的是"这组参数的优势稳不稳"时，事先写定的参数邻域扰动是必需证据：没做记"未检验"，结论最高"证据不足"，不能标"不适用"。
7. 成本 ×2 等情景用已冻结的成本假设，是压力测试，不是搜索：不计入 N，不用来挑方案。
8. 用配对接口时，`paired_sharpe_diff(left=基准, right=候选)` 的结果是候选 − 基准；`compare_candidates` 同一方向。报告里的差值一律写成候选 − 基准。

## 六、何时停止迭代

用户每次结果不理想就微调重跑时，**明确点名一次**这个模式和它的代价：测试段已被消耗，尝试次数增加，紧缩扣减变大。不拒绝帮忙，但把代价写进报告。

出现下面任一信号，建议停止在这个想法上调参，改为记录否定结论或换结构：
- 平滑后高原消失；紧缩夏普 ≤ 0；现实成本下优势消失；区域只是几个零散格子；始终说不出机制。
- 最近 3 轮迭代的主指标几乎不变（极差很小），或已迭代 ≥ 3 轮、主指标仍不升。
- 同一方案"改了再审"已到 2 轮仍需修改：降为"仅研究"。

换结构（换信号来源、换持有期、换标的、改优化目标）是**新的尝试**：计入尝试台账，并在没用过的数据上验证。每个转向方案写清"改了什么、为什么能解决触发的问题、预期会怎样失败"。否定结论也写成文档，避免下个季度重测同一个想法。
