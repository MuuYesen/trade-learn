# 报告格式

报告由你组织，可以加解读、图表和建议的下一步研究。下面这些内容**必须有**，顺序可以调整。报告短一些比长一些好：没人读的报告保护不了任何人。

## 一、结论（放在最前面）

一两句话说清结论，标明等级（无法判断 / 未证实 / 证据不足 / 目前可信），并对照第 1 步写下的判定标准。各级的条件、写法和下一步只看 `gates.md` 第一节的"结论分级"表，这里不重复。

紧接着列三项：验证链路是否有效、研究结论、能否进入模拟盘（测试段是否首次使用），以及**证据缺口表**。触发的门槛全部列出，每条写观测值、门槛和方向。

**不要**：只有样本内结果时写"更优""有效""全面优于"；样本外不显著时写"策略无效"（数据支持的只是"没有显著的净收益"）；"目前可信"时建议直接投入资金；用加权总分代替门槛。

## 二、立题

- 机制：为什么会赚钱、交易对手是谁；想法来源（是否在这份数据上已知有效）
- 规则：入场、出场、仓位、过滤条件
- 证伪条件与判定标准，以及它们是在看结果之前写下的；与 `gates.md` 默认值不同的阈值
- 训练段与测试段的切分点；行情的定义
- 证据来源分级：可复现的回测和成交记录为高，结构化日志为中，一次性观察和未经检验的设想为低。两个指标共用同一份上游数据，不算两个独立确认；AI 或人提出的设想和真实观测分开标注

## 三、数据

- 标的、来源、频率、区间与根数
- 复权方式，时区与交易时段；加密货币写明日线的切分时刻
- 缺失、跳空、停牌、成交量为 0 的情况；时钟审计结果
- 标的池是否包含已退市标的；基本面数据是否按发布日期对齐；每个字段的可用时间来源
- 数据资格漏斗：每层的数量（`data-audit.md` 第七节）

## 四、假设

- 手续费、滑点、其他费用的取值和依据
- 成交方式（下一根开盘、收盘……）、同根 bar 双触发的处理、是否只做多
- 用户没指定、由你采用的默认值，单独列出

## 五、结果

- **头条数字：样本外（滚动验证拼接结果，与最终测试段并列）、扣除成本、无前视偏差。** 样本内或未扣成本的数字只作对照，并标明
- 关键指标：年化收益、波动率、夏普（**附标准误**）、索提诺、最大回撤（附观测跨度和水下持续时间）、卡玛、换手、交易次数（往返笔数）、有效观测数、胜率（附 Wilson 区间）、盈亏比；毛收益与净收益并列；VaR 与 CVaR
- **引用 TradeLearn 的计算结果并写明口径**（年化按多少期、是否扣除无风险利率、夏普用哪种写法）；**用权益曲线独立复算**关键指标作核对，有出入说明原因
- 训练段与测试段**分开列**
- 期末持仓与未实现盈亏
- 与基准并列（默认同标的买入持有；截面策略用等权可交易池）
- 63 期滚动夏普，看优势是否在衰减。公式：窗口均值 ÷ 窗口标准差 × sqrt(年化期数)
- 资金账、归因、成本拆分都要闭合：期初资金 + 盈亏 − 成本 = 期末权益；各项之和等于总数；全程保留完整精度，只在展示时舍入

## 六、参数曲面与尝试次数

- 参数热力图，标出稳定区域；区域体检（覆盖率、连通、是否贴边）
- 稳定区域的整体表现（不是单个最优点），以及样本内最优格的样本外表现作对照
- **总尝试次数 N** 及其取法，原始夏普与紧缩夏普并列；做了 PBO、CPCV、Reality Check 就写出

## 七、稳健性

逐项写结果，没做的写"未检验"。每项写观测值、默认门槛和是否通过（`gates.md` 第三节）：

- 运气：夏普置信区间、有效观测数（两种口径）、蒙特卡洛分布
- 搜索：紧缩夏普、PBO、CPCV 路径分布、滚动验证各折结果
- 行情：对基准的残差 alpha、随机择时或随机篮子、分年度、分行情
- 错误：截断重算与未来扰动、从持仓重建收益、流程自检
- 脆弱：成本 ×2 / ×3、盈亏平衡成本、去掉最好的几天和最好的一年、换标的、压力情景

审计别人的回测时，另列**缺陷清单**：每条的严重度、证据、修复和复检动作（`gates.md` 第四节）。

## 八、失败与局限

- **没成立的部分**：哪些年份、哪些标的、多高的成本下收益消失。只展示成立部分的报告，犯的正是这套流程要防止的选择性错误
- 至少说明：样本是否覆盖不同行情、成本假设的不确定性、数据本身的问题
- **事实和推断分开写**；已证实的问题与缺少证据的地方分开列，缺少证据的不写成"通过"

## 九、记录与复现

- 这次运行记在哪个实验记录里，包括尝试计数、失败的方案、数据使用记录（测试段是否首次使用）
- 复现所需：数据来源与快照、代码版本、主要依赖版本、全部参数、随机种子、运行命令（`experiment-log.md` 第五节）
- 同一指标在不同来源对不上的，列出来

## 十、下一步

没通过时，判断更像数据、逻辑、成本还是行情的问题，再给出**最多三个**最值得做的下一步实验。用户在同一份数据上反复微调时，按 `gates.md` 第六节点名一次并给出停止信号。

## 十一、声明

结尾写：本报告仅供研究参考，不构成投资建议。

## 十二、交付前自检

- **单位**：基点、百分比、百分点不混用（"加息 25 个基点"，不是"25%"）；每个数写单位；期货写明每单位还是每手。
- **加总**：权重合计在 100% 附近（含现金或"其他"）；分组之和等于总数。
- **日期**：日期与星期一致；注意休市日、夏令时、跨年。
- **有符号、可能为 0 的序列**（如利差）的变化用差值，不用百分比变化。比较阈值前先按数据精度舍入。
- **同一个数在不同表里一致**。
- **每条解读能指到具体的结果字段**：所有数值都来自计算结果，叙述不改写任何数字；一条解读找不到对应的字段或输出文件，就删掉它。
- 分母为 0 的比率写"无"，不写 0。

---

**实盘复盘报告**另外要有：实盘数据来自哪种方式（Sentinel 查询、本机日志、下载原文）及数据截止时间、对照的时间段、核账结果与净值来源、是否按设计运行、实盘落在模拟分布的哪个分位、成本偏差与信号偏差各自多少、分层排查停在哪一层（首个成立的层）及证伪条件与复核触发、归因是否闭合、是否触发事先写好的停用条件，以及对回测假设的修正。有告警或停用规则时附告警事件表（`live-improve.md` 第八节）。实盘数字以 Sentinel 的口径为准。
