# 流程自检：先证明验证流程本身没问题

流程本身的 bug（前视、剔除漏网、收益错位、指标换算错）会污染之后的每一个结果，而且在真实数据上看不出来。所以在真实数据上跑滚动验证、下结论**之前**，先过这一页。判读线见 `gates.md` 第三节"链路"一行。

- 任何一项不过，结论是"无法判断"，不评价策略。
- **失败时只在合成数据上排查和修流程**，不在真实结果上调。如果测试设计本身被证明有误要调整，写进事先登记的方案并说明。
- 每次改了数据、特征、标签或选择流程，重跑相关的几项。

## 一、什么时候做哪几项

| 情形 | 至少做 |
|---|---|
| 任何回测 | 第二节的截断重算和延迟一根；第五节；第六节 |
| 有参数选择或滚动验证 | 再加第三节、第四节的符号翻转和植入效应 |
| 机器学习或跨期标签 | 再加第三节全部、第二节的未来扰动和哨兵行 |
| 审计别人的检查工具或复盘器 | 第七节 |

## 二、前视与因果

- **截断重算，比仓位**：取一个或多个历史日期 dt，把**原始数据**截到 dt，从头重跑整条流程（特征、选参、仓位、杠杆上限、风控），不从已跑完的结果里切片。dt 之前每一天的**最终仓位**（不只是信号）必须完全一致；截断前最后一天排除，因为截断版本会在那天被迫平仓。前视常藏在仓位层：例如一个风险上限对所有早期年份用了最后一年的估计，信号层看不出来。
- **未来扰动**：保持切点及以前的输入不变，把切点之后的输入换成极端值、随机游走、缺失或打乱，重算后切点及以前的输出必须不变。截断重算发现不了"全样本标准化后又回填历史"这类间接依赖，扰动可以。
- **切点要打到敏感位置**：除了固定比例（10%、25%、50%、70%、90% 附近）和固定位置，在每个敏感点 x 周围取 x−10、−5、−2、−1、x、+1、+2、+5、+10。敏感点来自窗口长度、预热期、`min_periods`、shift、重采样或交易时段边界、调仓日、换月日、成分重构日、历史上出过问题的位置。
- 发现问题时报告：第一个失败的切点和位置、测试类型、最大差异，再在失败点附近加密扫描。
- **哨兵行**：故意插入一条可用时间在未来的观测，跑完整个流程，这条记录必须被排除、结果不变。能查出"按发布日而不是可用日连接"这类截断查不到的泄漏。
- **打乱标签**：用打乱的目标跑同一条流程，结果应接近 0。
- **时点单元测试**：构造人工持仓和收益（例如只有第 3 根持仓为 1），检查 t 收盘建立的持仓只拿到 r[t+1]。
- **选择流程的因果性**：把第一个滚动测试窗口起点之后的收益随意改掉，第一个窗口选中的候选必须不变。
- **信号接在输入上**：改动 t 日及以后的价格，t 日的策略收益不变，之后的调仓应该随之改变。
- **成本单调**：提高成本时，毛收益和换手不变，同一候选的累计净收益不能上升。
- **延迟一根**：成交整体推后一根，收益大幅消失时，确认不是用到了当根价格。
- 措辞：写"本次数值测试没有发现未来输入改变历史输出"，**不写"证明没有未来函数"**，并写出漏检条件：差异被 sign、clip、rank 抹平；低于容差；没触发含问题的代码分支；有缓存或随机性。扰动运行之间隔离缓存，固定随机种子。

## 三、切分是否真的生效

- **数重叠**：每种验证方式独立统计"保留下来的训练样本中，信息区间与测试区间重叠的个数"，安全方式必须为 0。
- **故意放一条不安全的对照**：同一份数据、同一个模型，并排跑打乱的 k 折、按时间但不剔除、剔除、剔除加间隔。不安全对照的重叠数应大于 0，证明检查能发现问题。
- 不能用"安全与不安全方式的分数差不多"推出"没有泄漏"：分数差只作诊断，硬标准只有"重叠数为 0"。

## 四、流程能否"在噪声里找不到、在真效应里找得到"

- **符号翻转零假设**：每期收益乘以随机 ±1，波动不变、可预测性被破坏。在这份数据上跑完整的选择与滚动验证，样本外夏普应接近 0。同时记录各期被选中配置的样本内夏普中位数：它与样本外的差距，就是这套选择流程制造的虚高，写进报告。
- **植入效应**：在零假设数据上，给第一组配置的每个持仓期加一个已知漂移，强度使全样本 t 值约为 5（t ≈ 1.5 的效应任何诚实方法都看不见，不能拿来当测试）。流程必须在样本外找回它。
- **已知真值的多路径**：用信号强度已知的合成过程（例如 AR(1)，φ = 0.05）生成几百条路径，每条上原样重跑整套流程（扫描、挑选、样本外、PBO、DSR），报告各指标的中位数和 5%/95% 分位，以及"样本外显著为正"的路径占比。再跑一次强度为 0 的版本，得到流程的假阳性率。单条路径上的 PBO 或 DSR 本身也是一次抽样。
- **PBO 能否识别过拟合**：构造一个只在某种行情里有效的候选矩阵，PBO 应明显偏高（例如 ≥ 0.75）。识别不出来，说明 PBO 的实现有问题。

## 五、合理性

引用任何指标之前先看：
- **好得不像真的**：日频简单策略夏普 > 2；样本内外几乎一样好；胜率 > 90% 而回撤 < 5%；年化收益 > 50% 而回撤 < 5%。先当作泄漏或 bug，查明原因才继续。
- **暴露时间**（持仓时间占比）不接近 0%（多半是 bug），也不接近 100%（那就是基准）。权益曲线不平。
- **预热**：前 N 根让最长的指标完全成形，期间不交易。
- **最长空仓期**：4 年里空仓 3 年，实际只检验了 1 年。
- **截面回测的结构量级**（多头、持有 H 期、每期取前 X% 等权时）：平均持仓数约为"股票池规模 × X%"的 0.7–1.1 倍；日均单边换手约为 2/H 的 0.5–1.5 倍；策略的年化夏普一般应低于因子的**年化** IC_IR（每期 IC_IR × √每年调仓次数）——组合构建、只做多和成本都会损失一部分信息；明显超过它，先查收盘成交、没扣费、T+0、没剔除涨跌停。这只是定性提示，不设固定区间：只做多的夏普里含市场收益，重叠持有期的 IC 有自相关，比值会被扭曲；A 股多头最大回撤浅于 5% 几乎一定是前视；持仓数等于 1 或等于整个股票池都要查。
- **单格复跑**：网格里任取一格单独再跑，值必须一致（见 `validation.md` 第四节）。

## 六、指标换算核对

从成交记录到统计输入，下面这些都会给出"看起来合理"的数字，而且偏向好看的方向：
- **笔数用往返交易，不用成交笔数**：一笔往返包含两次成交，用成交笔数会让样本量约翻倍。
- **按标的追踪持仓，回到 0 才算一笔往返结束**，不把成交两两配对（做空、分批加减仓、多标的交错时配对会错）。盈亏由整个周期的现金流算出。
- **胜率与平均盈亏口径一致**（都扣费后），同时保留毛收益核对。零收益交易单独归类，不算赢也不算输。
- **回撤符号**：引擎通常把最大回撤记为负数，传给需要正幅度的计算时会被当成"完美"。最大回撤缺失时**不用 0 代替**。
- **盈亏比带状态**：有限值 / 无亏损 / 毛盈毛亏都为 0 / 溢出。"无亏损"不等于盈亏比很好，非有限状态转人工复核。分母为 0 的比率输出空值，不输出 0。
- **夏普口径**：写明是"算术均值 × 年化期数 − 无风险利率，再除以年化波动"还是"几何年化收益 ÷ 年化波动"；胜率按交易还是按天。两个来源对不上，先查口径。
- **停止交接**：没有完整的往返交易；最大回撤缺失或非有限值；引擎胜率与独立配对算出的胜率差超过 1 个百分点。查明哪边错之前，数字不进报告。
- **重建收益**：从持仓重建的收益与引擎报告的收益相关 ≥ 0.99、年化差 < 0.25%。

## 七、检查工具本身的对照

审计复盘器、一致性判定器、泄漏检查器这类工具时：
- **阳性对照**：按参考口径生成的数据，必须判为"一致"或"通过"。
- **阴性对照**：每次只改一个口径生成数据，必须判为"不一致"。阴性对照产生 0 条差异，说明这个对照没生效（例如样本太小，改动没触发任何交易），计为失败。
- 用工具自己合成的数据去测工具，结论只能是"无法判断"：这只证明链路接通。
- 每条记录带来源标记，跟着数据走；改文件名或换目录不能把合成数据变成真实数据。

## 八、回测出数前的两项自检

轻量回测也执行。先对齐候选与评估区间，再引用指标。判读见 [gates.md](gates.md)。

1. **成交**。对每个要报告的候选和区间，记录期初持仓、预热后应改变目标持仓的信号次数、实际成交通知数及最长空仓期。成交次数从该区间的成交记录（`stats.fills`）数出来，区分成交和往返交易。区间内有改变仓位的意图却零成交时，对照首个应下单的信号，追踪委托是否产生（`stats.orders`）、拒单原因、下单单位、最小数量、可用资金和费用。有意空仓、跨区间沿用持仓、真实市场约束下无法成交，都写清依据。未查明前，该候选该区间的结果不得进入策略评价或排名。
   - TradeLearn Lite 0.3.6 中，`buy()` 默认数量为 1，按目标比例下单会把数量截成整数（`backtest/targets.py` 取 `int()`），Lite 不支持非默认 `lot_size`。用小额资金跑高单价标的时，先查当前安装版本的真实签名和成交明细，按标的单位验证小数数量（例如 `self.buy(size=现金 / 价格)`）或合适的交易单位确实能成交。前一轮实测中固定买入 1 BTC 导致现金不足、测试段零成交，就是这一类。
   - 连续运行的策略在报告测试段时，从连续成交与权益序列按时间切片，保留期初持仓。若研究设计要求重置资金或持仓，事先记录重置规则，并提供指标所需的预热数据。
2. **年化期数**。报告任何年化指标前，用 `periods_per_year(市场, bar)` 得到按市场时钟的期数，用 `metric_periods_ok(stats.metric_metadata, "sharpe", 期数)` 核对框架结果；不一致（例如 0.3.6 日内回测的 `period_source = default_per_bar_profile`、periods = 252）时，用 `tradelearn.metrics.sharpe(returns, periods=期数)` 重算并在口径表里写明。
3. **夏普标准误与推断接口**。报告标准误时，先写明口径（IID、HAC 或块自助，见 [validation.md](validation.md#三有效观测数与显著性)），确认夏普的频率和年化期数与输入收益序列一致。统计只用已安装 TradeLearn 的实现；出数前用 `native_known_answers()` 以冻结输入核对它们（HAC 的冻结答案、配对差方向为候选 − 基准、N = 1 时 DSR 必须拒绝、MinTRL 的冻结答案）。结果为"不过"时停下报告；为"受阻"（旧版本没有该接口）时，只能报 IID 口径（`annual_sharpe_se`），HAC、配对差、PSR/DSR 记"受阻"。

把 [backtest_checks.py](../scripts/backtest_checks.py) 加到本次研究脚本的导入路径。下面的示例可在 Skill 的 `scripts/` 目录运行；成交检查输入应来自同一个候选与区间。

```python
from math import isclose
from backtest_checks import (
    annual_sharpe_se, native_known_answers, needs_fill_review,
    periods_per_year, metric_periods_ok,
)

# 已知答案：4 年、加密货币日频、年化夏普 1.0 → 0.5003423；
# 漏除 q 的错误写法 sqrt((1 + S²/2) / T_年) 会得到 0.6123724。
assert isclose(annual_sharpe_se(1.0, 1460, 365), 0.500342348545, abs_tol=1e-9)

status = native_known_answers()   # 例：{"sharpe_se": "通过", "paired_sharpe_diff": "通过", ...}
assert "不过" not in status.values(), status

assert not metric_periods_ok({"sharpe": {"periods": 252}}, "sharpe", periods_per_year("crypto", "30min"))
assert needs_fill_review(position_change_expected=True, fill_count=0)
assert not needs_fill_review(position_change_expected=False, fill_count=0)
```
