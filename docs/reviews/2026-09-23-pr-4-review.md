## 阻断问题

以下文件/行号均指 PR head。

1. **P1 多标的撤单仍会成交。** `tradelearn/backtest/broker.py:825-837` 只缓冲撤单，`rust/tradelearn-rust/src/runner.rs:339-361` 没有消费缓冲。相同策略第一天挂买入限价 9，第二天取消，后续最低价 7：单标的最终 Canceled/持仓0，多标的最终 Completed/持仓1。所有 runner 必须统一撤单同步。
2. **P1 OCO 同一根 bar 仍双边成交。** `broker.py:850-860` 在收到成交后才撤销兄弟单，此时 Rust 已经处理整根 bar。实测市价买入1单位并挂止损9/止盈11，后续 bar high=12/low=8，三张订单均 Completed，最终持仓 **-1**。互斥必须在撮合时生效，而非成交后仅撤销未来挂单。
3. **P1 有效期检查晚于撮合，过期订单仍成交。** `broker.py:1043-1048`、`engine.py:1438-1441`。订单有效期截至1月3日，1月4日首次触及买价，得到 `Expired -> Completed` 且持仓1。应在当根 bar 撮合前过滤过期订单。
4. **P1 有效期按数据源缓存，串用不同订单期限。** `broker.py:945-948` 用 `id(order.data)` 缓存 deadline；同一标的第一单 valid=None 时，第二张已过期订单也保持 Accepted。deadline 应逐订单计算/缓存。
5. **P1 smart 跟踪止损不更新水位。** `rust/tradelearn-rust/src/engine.rs:332-342` 原样保留未成交订单。卖出跟踪单 reference=100、trail=10，行情最高到120再回落105：普通模式第三根bar成交105，smart模式始终不成交。
6. **P1 smart 跟踪止损限价单忽略限价。** `matching.rs:335-352` 合并 StopTrail 和 StopTrailLimit 分支却未读取 limit_price。实测卖出limit=95，整根bar最高85，竟成交80。
7. **P1 多标的路径丢弃跟踪参数。** `runner.rs:227-228,360-361` 提交时硬传 None/None，跟踪单无法正常触发。应传递对应订单 trail 参数，覆盖所有 runner。
8. **P2 首次水位更新可能放松止损。** `engine.rs:240-241,440-441` 更新没有结合初始参考价。reference=120、trail=20，首根bar high=110/low=101，止损线由100降到90；下一根low=95未触发。
