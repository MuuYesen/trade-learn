## Findings and accepted changes

The report is partly reproducible on current master. Orders history reads the final broker cursor instead of the submission time, execution time is absent, and bracket helpers create orders even when a side's execution type is None. New regression tests reproduce these gaps (24 failures before the patch).

The merge retains PR authorship/history and adopts the independent corrections: submission/execution timestamps, requested price/limit and parent/OCO references, and buy/sell bracket suppression with None placeholders. Existing tag and copied info metadata remain available. New dataclass fields are appended to preserve positional argument compatibility.

Independent review additionally reproduced an asynchronous-feed defect in the proposed timestamp approach: a Jan 3 submission filled on Jan 4 was reported as Jan 4/Jan 6. Submission timestamps now use the strategy clock; execution/fill timestamps use the target feed cursor, with negative/out-of-range cursors rejected. Four additional native/Python multi-feed tests failed before this correction and pass afterwards. The bracket documentation does not promise transmit batching that the broker does not implement.

## Preserved master behavior

Master already contains the reviewed 0.2.6 lifecycle implementation from PR #4: synchronized cancellations and notifications, identity-keyed deadlines, pre-match expiry, native OCO cancellation, bracket cleanup, and persistent trailing matching. Its 189 targeted lifecycle tests pass before modification. PR #6 is a parallel implementation, not a successor to those corrections.

Merge conflicts retain master's Rust engine, bindings, runner contracts, lifecycle states, tests, exact default, version 0.2.6, and lockfiles. The proposed smart default and unrequested progress-bar default changes are not adopted. No package release is performed; new changes are recorded under Unreleased. No production trading deployment is part of this PR review.

Supplying the existing local oracle's utils/performance files made that metrics module pass all 4 tests. No unrelated test source was changed or disabled; private/local fixtures are not committed.
